**Product:** SI Studio  
**Product Type:** Mobile Application (Android)  
**Target Platform:** Android Smartphones and Tablets  
**Target Users:** Digital Hardware Engineers, PCB Designers, Signal Integrity Engineers  
**Development Environment:** Claude Code  
**Document Version:** 1.1  
**Primary Objective:** Quick Signal Integrity Analysis for PCB Layout Design

---

# 1. Product Overview

## 1.1 Problem Statement

Digital Hardware Engineers designing high-speed PCB layouts must consider numerous electrical and physical parameters to ensure Signal Integrity (SI).

These parameters include:

- Trace length
- Trace width and spacing
- Characteristic impedance
- PCB stackup
- Dielectric constant (Dk)
- Dielectric height
- Copper thickness
- Termination resistance
- Driver impedance
- Receiver impedance
- Signal voltage
- Rise time and fall time
- Data rate
- Differential pair skew

Different communication protocols have different electrical requirements, including USB 2.0, USB 3.0, PCI Express (PCIe), and SPI.

Incorrect PCB routing or electrical configurations can introduce signal reflections, ringing, overshoot, undershoot, excessive propagation delay, impedance mismatch, and other SI-related problems.

Traditional SI simulation tools can require extensive configuration, specialized knowledge, and detailed simulation models.

There is an opportunity to create a lightweight mobile application that allows engineers to quickly evaluate PCB routing parameters and understand expected signal behavior.

## 1.2 Proposed Solution

SI Studio is an Android-based interactive Signal Integrity analysis application.

The user selects a communication protocol, enters the electrical and PCB layout parameters, and clicks:

**Generate Quick SI Analysis**

The application calculates the expected signal behavior and generates corresponding waveform visualizations.

The analysis should help engineers identify potential SI problems during PCB layout design.

Core functionality:

1. Protocol-specific parameter configuration.
2. PCB stackup and routing configuration.
3. Electrical and transmission-line calculations.
4. Time-domain waveform generation.
5. Signal Integrity metrics.
6. Identification of potential SI problems.
7. Engineering recommendations.
8. Optional signal propagation animation.

## 1.3 Product Vision

Build a portable engineering companion that allows Digital Hardware Engineers to perform preliminary SI assessments directly from their Android devices.

The application should prioritize:

- Engineering accuracy.
- Interactive waveform visualization.
- Mobile usability.
- Fast analysis.
- Clear interpretation of simulation results.
- Offline functionality.

# 6. Signal Integrity Simulation Engine

This is the most important component of SI Studio.

The waveform must be generated from actual electrical parameters entered by the user.

It must not be a static waveform or decorative visualization.

## 6.1 Simulation Inputs

- Protocol configuration.
- Data rate or clock frequency.
- Signal voltage.
- Rise time.
- Fall time.
- Trace length.
- Trace width.
- Trace spacing.
- Characteristic impedance.
- Driver impedance.
- Receiver impedance.
- Termination resistance.
- PCB dielectric constant.
- Dielectric thickness.
- Copper thickness.
- Differential skew.
- Receiver capacitance.

## 6.2 Required Electrical Models

### A. Transmission-Line Model

Calculate:

- Characteristic impedance.
- Propagation velocity.
- Propagation delay.
- Electrical length.
- One-way and round-trip delay.

### B. Reflection Model

Use the reflection coefficient:

Γ = (ZL - Z0) / (ZL + Z0)

Calculate reflection magnitude, timing, and multiple reflections where supported.

### C. Termination Model

Support:

- No termination.
- Series termination.
- Parallel termination.
- Source termination.
- Load termination.

Demonstrate how termination affects signal reflections and waveform quality.

### D. Signal Loss Model

Implement simplified frequency-dependent channel loss.

Where sufficient parameters are available, account for:

- Conductor loss.
- Dielectric loss.
- Frequency-dependent attenuation.

### E. Differential Signal Model

Support:

- Positive signal.
- Negative signal.
- Differential voltage.
- Common-mode voltage.
- Differential skew.
- Differential pair mismatch.

Vdiff = Vpositive - Vnegative

Vcommon = (Vpositive + Vnegative) / 2

### F. Signal Edge Model

Support configurable rise and fall times.

The generated waveform should respond to changes in transition time and signal loading.

# 8. Signal Integrity Analysis Results

After simulation, display an analysis summary.

## 8.1 Key Metrics

| Metric | Description |
|---|---|
| Characteristic Impedance | Calculated transmission-line impedance |
| Target Impedance | Protocol/configuration target |
| Impedance Deviation | Difference from target |
| Propagation Delay | Signal travel time |
| Reflection Coefficient | Reflection magnitude |
| Overshoot | Voltage above nominal high level |
| Undershoot | Voltage below nominal low level |
| Rise Time | Signal transition time |
| Fall Time | Signal transition time |
| Differential Skew | P/N propagation mismatch |
| Insertion Loss | Estimated channel attenuation |
| Return Loss | Estimated reflected signal level |

Only show metrics applicable to the selected protocol and simulation model.

## 8.2 Analysis Status

Use three classifications:

- Good: Within configured engineering limits.
- Warning: Potential SI concern requiring investigation.
- Critical: A configured electrical limit has been exceeded.

Classifications must be based on explicit thresholds.

## 8.3 Engineering Recommendations

Provide recommendations based on actual analysis results.

Examples:

**Impedance Mismatch**

Review trace width, dielectric thickness, dielectric constant, and reference-plane configuration.

**Excessive Reflection**

Review receiver impedance and termination configuration.

**Differential Skew**

Review differential pair routing and length matching.

**Excessive Propagation Delay**

Review trace length and timing budget.

Recommendations must explain the electrical reason behind each finding.

# 12. Technical Architecture

The application must be developed as a native-feeling Android mobile application.

## 12.1 Frontend

Recommended technologies:

- Flutter.
- Dart.
- Material 3 design system.
- fl_chart or a custom Flutter CustomPainter-based waveform renderer.

The waveform renderer should support efficient drawing of large datasets, zooming, panning, and interactive measurement.

## 12.2 Simulation Engine

Implement a modular, Dart-based simulation engine initially.

Separate modules:

- Transmission-line calculations.
- Impedance calculations.
- Reflection calculations.
- Termination models.
- Differential signal models.
- Channel loss models.
- Time-domain waveform generation.
- SI metrics analysis.

The simulation engine must operate independently from Flutter UI components.

Use background isolates for computationally intensive simulations when needed to keep the interface responsive.

Recommended technologies:

- Support modern Android devices.

# 14. Simulation Accuracy and Limitations

SI Studio is intended to be a preliminary engineering analysis tool, not a replacement for professional SI simulation and PCB electromagnetic analysis software.

The application must distinguish between:

**Level 1 — Analytical Calculations**

- Characteristic impedance estimation.
- Propagation delay.
- Reflection coefficients.
- Basic termination analysis.

**Level 2 — Behavioral Time-Domain Simulation**

- Signal propagation.
- Reflections.
- Ringing.
- Overshoot and undershoot.
- Simplified channel attenuation.
- Receiver waveform reconstruction.

**Level 3 — Advanced SI Simulation (Future Development)**

- IBIS-based driver and receiver models.
- S-parameter-based channel simulation.
- Frequency-dependent channel modeling.
- Crosstalk analysis.
- Via and connector discontinuity modeling.
- Advanced eye and jitter analysis.
- Protocol compliance analysis.

The application must clearly indicate which modeling level was used for each result.

Do not claim protocol compliance or guaranteed PCB performance from simplified models.

# 16. Acceptance Criteria

The initial application will be considered successful when:

1. Users can select SPI or USB 2.0.
2. The application displays protocol-specific parameters.
3. Users can enter PCB stackup and trace parameters.
4. Users can configure driver, receiver, and termination characteristics.
5. The application performs electrical calculations.
6. The application generates time-domain waveforms based on the entered parameters.
7. Changing trace length changes propagation delay.
8. Changing impedance changes modeled reflection behavior.
9. Changing termination changes the resulting waveform when electrically applicable.
10. The application displays meaningful SI metrics.
11. The application identifies potential SI concerns.
12. The application provides engineering recommendations.
13. Users can save and reload analysis configurations.
14. Users can export waveform data.
15. The application operates without an internet connection.
16. The application runs on Android smartphones and tablets.

# 17. Instructions for Claude Code

Claude Code should treat this document as the primary product specification.

Before implementing the application:

1. Inspect the existing repository.
2. Identify the current framework and architecture.
3. Review existing source files and reusable components.
4. Preserve existing working functionality.
5. Identify missing functionality against this PRD.
6. Propose an implementation plan before making major architectural changes.

Development principles:

- Use Flutter and Dart.
- Implement the application incrementally.
- Prioritize a functioning simulation engine over visual decoration.
- Separate mathematical calculations from waveform rendering.
- Keep protocol-specific parameters modular.
- Use documented engineering equations.
- Add unit tests for electrical calculations.
- Add test cases for known reflection and propagation-delay scenarios.
- Ensure waveforms respond to actual simulation outputs.
- Optimize waveform rendering for mobile devices.
- Keep the application functional offline.
- Do not generate arbitrary waveforms just to make the interface look interesting.
- Do not fabricate SI metrics or claim unsupported compliance.
- Clearly label approximations and assumptions.

### Important Development Instruction

Do not attempt to implement every protocol and every advanced SI feature simultaneously.

Start with SPI and USB 2.0.

First establish a reliable simulation engine that demonstrates the relationship between:

- Trace length.
- Characteristic impedance.
- Termination resistance.
- Rise time.
- PCB stackup.
- Signal reflection.
- Propagation delay.

Once these fundamentals are working, extend the architecture to USB 3.0 and PCIe.

The final objective is to create a reliable, extensible Android SI analysis application that Digital Hardware Engineers can use as part of their everyday PCB design workflow.
